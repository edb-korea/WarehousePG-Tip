## 1. EDB repository 및 설치 패키지 확인

`scdw`에서 EDB repository를 설정합니다.

```bash
export EDB_SUBSCRIPTION_TOKEN=<your-token>
export EDB_REPO=gpsupp

curl -1sSLf "https://downloads.enterprisedb.com/$EDB_SUBSCRIPTION_TOKEN/$EDB_REPO/setup.rpm.sh" | sudo -E bash
sudo dnf clean all
sudo dnf makecache
sudo dnf install -y dnf-plugins-core
```

정식 1.3 설치에 사용할 패키지 버전을 확인합니다.

```bash
sudo dnf list --showduplicates whpg-enterprise-manager
sudo dnf list --showduplicates edb-whpg-observability-collector
sudo dnf list --showduplicates edb-acp-host-agent
```

전체 기능을 구성할 때 사용하는 주요 패키지는 다음과 같습니다.

| 기능 | 패키지 |
| --- | --- |
| WEM UI/API | `whpg-enterprise-manager` |
| Observability Collector | `edb-whpg-observability-collector` |
| WEM host agent | `edb-acp-host-agent` |

Prometheus와 Loki는 WEM 외부 관측 스택으로 구성합니다.
Alertmanager는 WEM 1.3에서 WEM이 관리하는 내부 subprocess로 실행됩니다.
이미 운영 중인 관측 스택이 있으면 해당 endpoint를 재사용할 수 있습니다.

Safeguard/DR 구성은 별도 문서인 `18-5. WEM 1.3 Safeguard DR 구성.md`에서 다룹니다.

## 2. Prometheus 설치

`scdw`에서 실행합니다.

```bash
cd /tmp

curl -LO https://github.com/prometheus/prometheus/releases/download/v3.5.0/prometheus-3.5.0.linux-amd64.tar.gz
tar -xzf prometheus-3.5.0.linux-amd64.tar.gz

sudo useradd --no-create-home --shell /sbin/nologin prometheus || true
sudo mkdir -p /etc/prometheus /var/lib/prometheus
sudo cp prometheus-3.5.0.linux-amd64/prometheus /usr/local/bin/
sudo cp prometheus-3.5.0.linux-amd64/promtool /usr/local/bin/
sudo chown -R prometheus:prometheus /etc/prometheus /var/lib/prometheus
```

Prometheus 설정 파일을 생성합니다.

```bash
sudo tee /etc/prometheus/prometheus.yml > /dev/null <<'EOF'
global:
  scrape_interval: 15s

scrape_configs:
  - job_name: prometheus
    static_configs:
      - targets: ["localhost:9090"]

  - job_name: wem
    metrics_path: /prom/metrics
    static_configs:
      - targets: ["localhost:8080"]
EOF
```

systemd 서비스를 생성합니다.

```bash
sudo tee /etc/systemd/system/prometheus.service > /dev/null <<'EOF'
[Unit]
Description=Prometheus
After=network-online.target
Wants=network-online.target

[Service]
User=prometheus
Group=prometheus
Type=simple
ExecStart=/usr/local/bin/prometheus \
  --config.file=/etc/prometheus/prometheus.yml \
  --storage.tsdb.path=/var/lib/prometheus \
  --web.listen-address=0.0.0.0:9090 \
  --web.enable-remote-write-receiver

Restart=on-failure

[Install]
WantedBy=multi-user.target
EOF
```

기동 및 확인:

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now prometheus
sudo systemctl status prometheus --no-pager
curl http://127.0.0.1:9090/-/healthy
```

정상 응답:

```text
Prometheus Server is Healthy.
```

## 3. Loki 설치

`scdw`에서 실행합니다.

```bash
cd /tmp

curl -LO https://github.com/grafana/loki/releases/download/v3.5.0/loki-linux-amd64.zip
sudo dnf install -y unzip || true
unzip loki-linux-amd64.zip

sudo useradd --no-create-home --shell /sbin/nologin loki || true
sudo mkdir -p /etc/loki /var/lib/loki
sudo install -m 0755 loki-linux-amd64 /usr/local/bin/loki
sudo chown -R loki:loki /etc/loki /var/lib/loki
```

Loki 설정 파일을 생성합니다.

```bash
sudo tee /etc/loki/loki-local-config.yaml > /dev/null <<'EOF'
auth_enabled: false

server:
  http_listen_address: 0.0.0.0
  http_listen_port: 3100

common:
  path_prefix: /var/lib/loki
  storage:
    filesystem:
      chunks_directory: /var/lib/loki/chunks
      rules_directory: /var/lib/loki/rules
  replication_factor: 1
  ring:
    kvstore:
      store: inmemory

schema_config:
  configs:
    - from: 2024-01-01
      store: tsdb
      object_store: filesystem
      schema: v13
      index:
        prefix: index_
        period: 24h

limits_config:
  allow_structured_metadata: false
EOF
```

systemd 서비스를 생성합니다.

```bash
sudo tee /etc/systemd/system/loki.service > /dev/null <<'EOF'
[Unit]
Description=Loki
After=network-online.target
Wants=network-online.target

[Service]
User=loki
Group=loki
Type=simple
ExecStart=/usr/local/bin/loki -config.file=/etc/loki/loki-local-config.yaml
Restart=on-failure

[Install]
WantedBy=multi-user.target
EOF
```

기동 및 확인:

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now loki
sudo systemctl status loki --no-pager
curl http://127.0.0.1:3100/ready
```

정상 응답:

```text
ready
```

## 5. WEM DB용 PostgreSQL 설치

`scdw`는 WHPG standby coordinator로 5432 포트를 사용 중일 수 있습니다. WEM application DB용 PostgreSQL은 5433 포트로 구성합니다.

`scdw`에서 실행합니다.

```bash
sudo dnf install -y postgresql-server postgresql-contrib
sudo postgresql-setup --initdb
```

서비스 시작 전에 PostgreSQL 포트를 변경합니다.

```bash
sudo vi /var/lib/pgsql/data/postgresql.conf
```

다음 값을 설정합니다.

```conf
listen_addresses = '127.0.0.1'
port = 5433
```

기동:

```bash
sudo systemctl enable --now postgresql
sudo systemctl status postgresql --no-pager
ss -lntp | egrep '5432|5433'
```

`pg_hba.conf`에서 localhost password 인증을 설정합니다.

```bash
sudo vi /var/lib/pgsql/data/pg_hba.conf
```

예시:

```conf
host    all             all             127.0.0.1/32            scram-sha-256
host    all             all             ::1/128                 scram-sha-256
```

PostgreSQL reload:

```bash
sudo systemctl reload postgresql
```

WEM DB user와 database를 생성합니다. `pg_hba.conf`가 `scram-sha-256`이면 비밀번호를 SCRAM secret으로 저장해야 합니다.

```bash
sudo -iu postgres psql -p 5433
```

```sql
SET password_encryption = 'scram-sha-256';
CREATE USER wem_admin WITH PASSWORD '<wem_admin_password>';
CREATE DATABASE wem OWNER wem_admin;
GRANT ALL PRIVILEGES ON DATABASE wem TO wem_admin;
\q
```

접속 확인:

```bash
PGPASSWORD='<wem_admin_password>' psql -h 127.0.0.1 -p 5433 -U wem_admin -d wem -c "select current_user, current_database();"
PGPASSWORD='<wem_admin_password>' psql -h 127.0.0.1 -p 5433 -U wem_admin -d postgres -c "select current_user, current_database();"
```

WEM_PASSWORD=<wem_admin_password>

# Observability
PROMETHEUS_URL=http://192.168.10.75:9090

## 9. Host agent 구성

`edb-acp-host-agent`는 WEM 1.3에서 추가된 별도 host agent 서비스입니다. WEM이 WarehousePG coordinator 또는 standby coordinator host에서 권한이 필요한 작업을 실행해야 할 때, WEM이 직접 OS 명령을 실행하지 않고 host agent를 통해 작업을 위임합니다.

host agent는 WEM 내부 job execution engine에 접속합니다. 대표 사용처는 HBA Editor를 통한 `pg_hba.conf` 수정과 coordinator 권한 작업입니다. Safeguard/DR 구성은 별도 문서인 `18-5. WEM 1.3 Safeguard DR 구성.md`에서 다룹니다.

### 9.1 설치 대상

| 설치 대상 | 설치 여부 | 설명 |
| --- | --- | --- |
| Primary coordinator | 필수 | HBA Editor, coordinator 권한 작업 실행 |
| Standby coordinator | 필수 | standby coordinator 대상 권한 작업 및 HBA/config 작업 대응 |
| WEM 전용 서버 | 불필요 | WHPG coordinator/standby coordinator 역할이 아니면 설치하지 않음 |
| Segment host | 불필요 | 작업은 coordinator를 통해 실행 |

이 문서의 예시에서 `scdw`는 WEM 서버이면서 WHPG standby coordinator입니다. 따라서 WEM 전용 서버라서 제외하는 것이 아니라, standby coordinator 역할 때문에 host agent 설치 대상에 포함합니다.

설치 대상 예시:

```text
cdw
scdw
```

### 9.2 host agent 설치

`cdw`, `scdw`에서 EDB repository를 설정한 뒤 host agent를 설치합니다.

```bash
export EDB_SUBSCRIPTION_TOKEN=<your-token>
export EDB_REPO=gpsupp

curl -1sSLf "https://downloads.enterprisedb.com/$EDB_SUBSCRIPTION_TOKEN/$EDB_REPO/setup.rpm.sh" | sudo -E bash
sudo dnf clean all
sudo dnf makecache

sudo dnf install -y edb-acp-host-agent
rpm -q edb-acp-host-agent
```

### 9.3 host agent 설정

`cdw`, `scdw`에서 `/etc/edb/acp-host-agent/acp-host-agent.conf`를 수정합니다.

```bash
sudo vi /etc/edb/acp-host-agent/acp-host-agent.conf
```

예시:

```bash
--coordinator
WEM_CONNECT_ADDRESS=192.168.10.75:8081
WEM_TASK_QUEUES=coordinator-tasks
WEM_DATABASE=postgres
AGENT_LOG_LEVEL=info

--standby
WEM_CONNECT_ADDRESS=192.168.10.75:8081
WEM_TASK_QUEUES=standby-tasks
WEM_DATABASE=postgres
WHPG_DATA_DIR=/data1/coordinator/gpseg-1
AGENT_LOG_LEVEL=info
```

agent 기동:

```bash
sudo systemctl enable --now acp-host-agent
sudo systemctl status acp-host-agent --no-pager
sudo tail -n 100 /var/log/edb/acp-host-agent/acp-host-agent.log
```

정상 로그 예시:

```text
worker running task_queue=coordinator-tasks
```

### 9.4 권한

host agent가 수행하는 작업에 따라 `sudo`, gpadmin home, 작업 디렉토리 접근 권한이 필요할 수 있습니다. HBA Editor처럼 `pg_hba.conf`를 수정하는 기능을 사용할 경우 운영 보안 정책에 맞게 필요한 권한만 부여합니다.

테스트 환경에서는 다음처럼 passwordless sudo를 부여해 동작을 먼저 검증할 수 있습니다. 운영 환경에서는 최소 권한 sudoers 규칙으로 제한하는 것을 권장합니다.

```bash
echo 'acp-host-agent ALL=(ALL) NOPASSWD: ALL' | sudo tee /etc/sudoers.d/acp-host-agent
sudo chmod 440 /etc/sudoers.d/acp-host-agent
sudo visudo -cf /etc/sudoers.d/acp-host-agent
sudo -u acp-host-agent sudo -n true && echo sudo-ok
```

## 11. WEM 1.3 주의사항

### 11.1 WEM DB는 WHPG와 분리 권장

WEM application state DB는 모니터링 대상 WHPG와 분리된 PostgreSQL에 저장하는 것을 권장합니다.

`scdw`가 WHPG standby coordinator로 5432를 사용 중이면 WEM DB용 PostgreSQL은 5433 등 별도 포트를 사용합니다.

### 11.2 host agent 기본 DB

`acp-host-agent.conf`에서 `WEM_DATABASE`를 지정하지 않으면 기본값 `wem`으로 psql 접속을 시도할 수 있습니다. WHPG에 `wem` DB가 없으면 다음 오류가 발생합니다.

```text
FATAL: database "wem" does not exist
```

이 경우 coordinator 및 standby coordinator agent 설정에 다음을 추가합니다.

```bash
WEM_DATABASE=postgres
```
