# Cluster & Database Disk Quotas

**WarehousePG 7 · diskquota 2.4**

Cap how much disk space a whole cluster — or a single database — may use, and
have WarehousePG refuse over-quota writes automatically.

The `diskquota` extension already limits disk usage per **schema**, **role**, and
**tablespace**. Version 2.4 adds two broader scopes:

| Scope | What it caps |
|---|---|
| **Cluster quota** | The combined size of *every monitored database* in the cluster. |
| **Database quota** | The total size of *one* database. |

A background worker adds up sizes continuously. When usage crosses a cap, new
writes are refused until space is freed.

> All commands below were run on a live WarehousePG 7 / diskquota 2.4 cluster;
> the outputs shown are real.

---

## 1. Turn it on

Do this once per cluster, as a superuser.

**① Load the library and restart** (run from the coordinator host):

```bash
gpconfig -c shared_preload_libraries -v 'diskquota-2.4.so'
gpstop -ra
```

**② Create the extension** in each database you want to watch:

```sql
CREATE EXTENSION diskquota;
```

**③ Seed table sizes** — only needed if the database already has data (skip for
an empty one):

```sql
SELECT diskquota.init_table_size_table();
```

The cluster cap is stored by diskquota itself, so it survives restarts and can be
set from any monitored database. Each watched database runs its own lightweight
worker.

---

## 2. Set a quota

| Goal | Command |
|---|---|
| Cap the whole cluster | `SELECT diskquota.set_cluster_quota('500 GB');` |
| Cap one database | `SELECT diskquota.set_database_quota('salesdb', '100 GB');` |
| Raise / lower a cap | Run the same command again with a new size |
| Remove a cap | Set the size to `'-1 MB'` |

Sizes accept plain units — `'2 TB'`, `'500 GB'`, `'250 MB'`.

```sql
-- Keep the whole cluster under 1 TB, and hold "reporting" to 50 GB.
SELECT diskquota.set_cluster_quota('1 TB');
SELECT diskquota.set_database_quota('reporting', '50 GB');
```

Setting the cluster cap tells you which databases it can’t see (any database
without the extension):

```
WARNING:  cluster quota counts monitored databases only; not monitored: contrib_regression, isolation2test
HINT:     run CREATE EXTENSION diskquota in those databases to include them
```

---

## 3. Check usage

Two views show each cap next to the space actually used.

```sql
SELECT * FROM diskquota.show_cluster_quota_view;
```
```
 quota_in_mb | total_size_in_bytes
-------------+---------------------
      512000 |             1048576
```

```sql
SELECT * FROM diskquota.show_database_quota_view;
```
```
 database_name | quota_in_mb | total_size_in_bytes
---------------+-------------+---------------------
 quota_demo    |         100 |             1048576
```

The overall worker state:

```sql
SELECT diskquota.status();
```
```
              status
----------------------------------
 ("soft limits",on)
 ("hard limits",off)
 ("current binary version",2.4.0)
 ("current schema version",2.4)
```

> **The views refresh once per cycle.** A cap or a size change appears in these
> views (and takes effect) after one worker cycle — see *naptime* below. To wait
> for that in a script, call `SELECT diskquota.wait_for_worker_new_epoch();`.

---

## 4. How enforcement works

Once a database or the cluster is over quota, writes are stopped. There are two
modes:

| Mode | When it acts | How to enable |
|---|---|---|
| **Soft limit** *(default)* | Rejects a new `INSERT` / `UPDATE` / `COPY` **before** it runs. | always on |
| **Hard limit** | Stops an over-quota query **while** it runs, on the segments. | `diskquota.hard_limit = on` |

A rejected write reports exactly why:

```
ERROR:  database's disk space quota exceeded with name: salesdb
HINT:   database usage 152 MB exceeds database quota 50 MB; free disk space or raise diskquota.set_database_quota()
```
```
ERROR:  cluster's disk space quota exceeded
HINT:   cluster usage 122 MB exceeds cluster quota 40 MB; free disk space or raise diskquota.set_cluster_quota()
```

**Recovery is automatic.** Free space (drop or truncate data, or raise the cap)
and writes are allowed again on the next cycle — no restart, no manual reset.

---

## 5. Pause & resume

Temporarily stop enforcement — for a bulk load or maintenance — without changing
any caps:

```sql
SELECT diskquota.pause();     -- stop rejecting writes
SELECT diskquota.resume();    -- turn enforcement back on
```

---

## 6. Tuning: naptime

`diskquota.naptime` (seconds) sets how often the worker recomputes sizes and
refreshes the views. Lower it for faster reaction; raise it to reduce overhead.

```bash
gpconfig -c diskquota.naptime -v 2
gpstop -ra
```

After you free space, allow up to one naptime before writes resume.

---

## 7. Good to know

- **Only watched databases count.** A database without `CREATE EXTENSION diskquota`
  is neither counted in the cluster total nor limited by it. `set_cluster_quota()`
  warns you which databases it can’t see.
- **diskquota exempts itself.** Its own workers and bookkeeping tables don’t count
  toward any cap — otherwise you could never free space or raise a limit once full.
- **Dropped databases stop counting.** If a database is dropped without
  `DROP EXTENSION`, its last recorded size is released automatically.
- **Cluster and database caps are independent.** A write must satisfy *both* —
  whichever is tighter wins.
- **WarehousePG 7 only.** The cluster and per-database quotas ship in diskquota 2.4
  for WarehousePG 7. Schema, role, and tablespace quotas remain available on
  earlier lines.

---

## 8. Quick reference

| Command | Purpose |
|---|---|
| `diskquota.set_cluster_quota('size')` | Cap the whole cluster (`'-1 MB'` to remove) |
| `diskquota.set_database_quota('db','size')` | Cap one database (`'-1 MB'` to remove) |
| `diskquota.show_cluster_quota_view` | Cluster cap vs. usage |
| `diskquota.show_database_quota_view` | Per-database cap vs. usage |
| `diskquota.init_table_size_table()` | Seed sizes on a non-empty database |
| `diskquota.pause()` / `diskquota.resume()` | Suspend / restore enforcement |
| `diskquota.status()` | Show worker state |
| `diskquota.wait_for_worker_new_epoch()` | Block until the next refresh (scripts) |

| Setting | Default | Meaning |
|---|---|---|
| `diskquota.hard_limit` | `off` | Stop over-quota queries mid-execution |
| `diskquota.naptime` | `2` | Seconds between size refreshes |

*Run the SQL functions as a superuser from any monitored database.*
