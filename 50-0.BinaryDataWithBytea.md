# WarehousePG 바이너리 데이터(이미지, PDF, 문서) 저장 가이드

## 0. 핵심 전제 — Large Object가 아닌 BYTEA를 사용해야 합니다

WarehousePG는 PostgreSQL의 Large Object(OID 기반, `lo_import`/`lo_export`/`\lo_*`) 기능을 지원하지 않습니다.

대신 **`BYTEA`** 타입 컬럼을 사용합니다.

> BYTEA와 TEXT 컬럼으로 수백 메가바이트에 달하는 대용량 데이터를 저장할 수 있습니다.

즉, PostgreSQL에서 흔히 쓰는 large object 방식은 WarehousePG에서 안 되고, **`BYTEA` 타입 컬럼**으로 저장해야 합니다.

## 1. DDL — 파일 저장용 테이블

```sql
CREATE TABLE file_store (
    file_id         bigserial,
    file_name       text NOT NULL,
    mime_type       text,               -- 'image/png', 'application/pdf' 등
    file_ext        text,               -- 'png', 'jpg', 'pdf' 등
    file_size_bytes bigint,
    checksum_sha256 text,               -- 무결성 검증용
    file_data       bytea NOT NULL,     -- 실제 바이너리 데이터
    uploaded_by     text,
    uploaded_at     timestamp DEFAULT now()
)
DISTRIBUTED BY (file_id);
```

> **참고:** PNG/JPEG/PDF는 이미 자체적으로 압축된 포맷이라, AO/AOCO 테이블의 압축(`compresstype=zstd` 등)을 걸어도 이득이 거의 없고 CPU만 더 씁니다. 이 케이스는 **일반 heap 테이블(기본값)**로 두는 것을 권장합니다.

> 아래는 AOCO 로 한 경우. 
```sql
CREATE TABLE file_store (
    file_id         bigserial    ENCODING (compresstype=zstd, compresslevel=1),
    file_name       text         ENCODING (compresstype=zstd, compresslevel=3),
    mime_type       text         ENCODING (compresstype=RLE_TYPE, compresslevel=4),  -- 값 종류가 적어 반복 많음 (image/png, application/pdf 등)
    file_ext        text         ENCODING (compresstype=RLE_TYPE, compresslevel=4),  -- 마찬가지로 저카디널리티
    file_size_bytes bigint       ENCODING (compresstype=zstd, compresslevel=1),
    checksum_sha256 text         ENCODING (compresstype=zstd, compresslevel=1),      -- 해시값이라 압축 효율 낮음, 가볍게만
    file_data       bytea        ENCODING (compresstype=none),                       -- 이미 압축된 바이너리(PNG/JPEG/PDF) → 재압축 무의미, CPU만 낭비
    uploaded_by     text         ENCODING (compresstype=RLE_TYPE, compresslevel=4),  -- 업로드 계정 수는 한정적
    uploaded_at     timestamp    ENCODING (compresstype=RLE_TYPE, compresslevel=4)   -- 시계열 데이터, delta 압축 자동 결합
                                 DEFAULT now()
)
WITH (
    appendonly=true,
    orientation=column,
    compresstype=zstd,      -- 컬럼별 지정 안 한 경우의 테이블 기본값
    compresslevel=3,
    blocksize=32768,
    checksum=true
)
DISTRIBUTED BY (file_id);
```

## 2. DML — 데이터 삽입 (2가지 방법)

### 방법 A: psql에서 서버에 이미 있는 파일 읽기 (`pg_read_binary_file`)

서버(coordinator) 로컬 디스크에 파일이 이미 있고, superuser 권한이 있을 때만 가능합니다.

```sql
INSERT INTO file_store (file_name, mime_type, file_ext, file_size_bytes, file_data)
VALUES (
    'sample.png',
    'image/png',
    'png',
    pg_column_size(pg_read_binary_file('/data/uploads/sample.png')),
    pg_read_binary_file('/data/uploads/sample.png')
);
```

### 방법 B: 클라이언트(내 PC)에서 업로드 — 실무에서 주로 쓰는 방식

클라이언트 머신에 있는 파일을 업로드하려면 애플리케이션 코드(Python 등)에서 바이너리로 읽어 파라미터 바인딩으로 넣어야 합니다. 아래 3번의 Python 스크립트를 사용하세요.

## 3. Python 스크립트 — 업로드/다운로드

파일명: `file_store_upload_download.py`

```python
#!/usr/bin/env python3
"""
file_store_upload_download.py
-----------------------------------------------------------------------
로컬 파일(이미지, PDF, 문서 등)을 WarehousePG의 file_store 테이블(BYTEA 컬럼)에
업로드하거나, 저장된 파일을 다시 로컬로 다운로드(export)합니다.

사전 준비 (DDL):
    CREATE TABLE file_store (
        file_id         bigserial,
        file_name       text NOT NULL,
        mime_type       text,
        file_ext        text,
        file_size_bytes bigint,
        checksum_sha256 text,
        file_data       bytea NOT NULL,
        uploaded_by     text,
        uploaded_at     timestamp DEFAULT now()
    )
    DISTRIBUTED BY (file_id);

사용 예:
    # 업로드
    python3 file_store_upload_download.py upload \
        --host mycoordinator --dbname mydb --user gpadmin \
        --file /path/to/photo.png --mime image/png

    # 다운로드 (file_id로 조회)
    python3 file_store_upload_download.py download \
        --host mycoordinator --dbname mydb --user gpadmin \
        --file-id 3 --outdir ./downloaded
-----------------------------------------------------------------------
"""

import argparse
import hashlib
import mimetypes
import os
import sys

import psycopg2


def parse_args():
    p = argparse.ArgumentParser()
    sub = p.add_subparsers(dest="command", required=True)

    common = argparse.ArgumentParser(add_help=False)
    common.add_argument("--host", required=True)
    common.add_argument("--port", default="5432")
    common.add_argument("--dbname", required=True)
    common.add_argument("--user", required=True)
    common.add_argument("--password", default=None)
    common.add_argument("--table", default="file_store")

    up = sub.add_parser("upload", parents=[common])
    up.add_argument("--file", required=True, help="업로드할 로컬 파일 경로")
    up.add_argument("--mime", default=None, help="MIME 타입 (지정 안 하면 자동 추론)")
    up.add_argument("--uploaded-by", default=None)

    down = sub.add_parser("download", parents=[common])
    down.add_argument("--file-id", required=True, type=int)
    down.add_argument("--outdir", default=".")

    return p.parse_args()


def get_conn(args):
    kwargs = dict(host=args.host, port=args.port, dbname=args.dbname, user=args.user)
    if args.password:
        kwargs["password"] = args.password
    return psycopg2.connect(**kwargs)


def do_upload(args):
    if not os.path.isfile(args.file):
        print(f"[ERROR] 파일을 찾을 수 없습니다: {args.file}", file=sys.stderr)
        sys.exit(1)

    file_name = os.path.basename(args.file)
    file_ext = os.path.splitext(file_name)[1].lstrip(".").lower()
    mime_type = args.mime or mimetypes.guess_type(args.file)[0] or "application/octet-stream"

    with open(args.file, "rb") as f:
        data = f.read()

    checksum = hashlib.sha256(data).hexdigest()
    size_bytes = len(data)

    conn = get_conn(args)
    cur = conn.cursor()
    cur.execute(
        f"""
        INSERT INTO {args.table}
            (file_name, mime_type, file_ext, file_size_bytes, checksum_sha256, file_data, uploaded_by)
        VALUES (%s, %s, %s, %s, %s, %s, %s)
        RETURNING file_id
        """,
        (file_name, mime_type, file_ext, size_bytes, checksum, psycopg2.Binary(data), args.uploaded_by),
    )
    file_id = cur.fetchone()[0]
    conn.commit()
    cur.close()
    conn.close()

    print(f"[DONE] 업로드 완료: file_id={file_id}, name={file_name}, "
          f"size={size_bytes:,} bytes, sha256={checksum}")


def do_download(args):
    conn = get_conn(args)
    cur = conn.cursor()
    cur.execute(
        f"SELECT file_name, file_data, checksum_sha256 FROM {args.table} WHERE file_id = %s",
        (args.file_id,),
    )
    row = cur.fetchone()
    if row is None:
        print(f"[ERROR] file_id={args.file_id} 를 찾을 수 없습니다.", file=sys.stderr)
        sys.exit(1)

    file_name, data, expected_checksum = row
    os.makedirs(args.outdir, exist_ok=True)
    out_path = os.path.join(args.outdir, file_name)

    raw = bytes(data)
    with open(out_path, "wb") as f:
        f.write(raw)

    actual_checksum = hashlib.sha256(raw).hexdigest()
    match = "OK" if actual_checksum == expected_checksum else "MISMATCH!"

    print(f"[DONE] 다운로드 완료: {out_path} ({len(raw):,} bytes)")
    print(f"[CHECK] 체크섬 검증: {match}")

    cur.close()
    conn.close()


def main():
    args = parse_args()
    if args.command == "upload":
        do_upload(args)
    elif args.command == "download":
        do_download(args)


if __name__ == "__main__":
    main()
```

### 실행 예시

```bash
# 이미지 업로드
python3 file_store_upload_download.py upload \
    --host mycoordinator.example.com --dbname mydb --user gpadmin \
    --file /home/user/photo.png --mime image/png --uploaded-by alice

# PDF 업로드
python3 file_store_upload_download.py upload \
    --host mycoordinator.example.com --dbname mydb --user gpadmin \
    --file /home/user/report.pdf --mime application/pdf

# file_id=3 다운로드
python3 file_store_upload_download.py download \
    --host mycoordinator.example.com --dbname mydb --user gpadmin \
    --file-id 3 --outdir ./downloaded
```

## 4. 순수 SQL로만 확인하고 싶을 때 (조회/메타데이터)

```sql
-- 저장된 파일 목록과 크기 확인 (실제 바이너리는 빼고)
SELECT file_id, file_name, mime_type, file_size_bytes, uploaded_at
FROM file_store
ORDER BY uploaded_at DESC;

-- 특정 파일 크기(바이트) 확인
SELECT file_id, file_name, pg_column_size(file_data) AS stored_bytes
FROM file_store
WHERE file_id = 3;

-- psql에서 직접 export (소량 테스트용)
\copy (SELECT file_data FROM file_store WHERE file_id = 3) TO '/tmp/exported_file.png' WITH (FORMAT binary)
```

## 6. 실무에서 고려할 점

### 6.1 대용량 파일(수백 MB~GB급 동영상 등)은 DB에 직접 저장 비권장

BYTEA는 이론상 컬럼당 1GB까지 가능하지만, 큰 값을 다루려면 메모리 사용량이 급증합니다. 실무에서는 보통:

- **파일은 S3/Object Storage에 저장**하고
- **DB에는 경로(URL)와 메타데이터만 저장**하는 구조를 더 권장합니다.

```sql
CREATE TABLE file_metadata (
    file_id         bigserial,
    file_name       text,
    storage_url     text,   -- s3://bucket/path/to/file.png
    mime_type       text,
    file_size_bytes bigint
) DISTRIBUTED BY (file_id);
```

### 6.2 백업/복원 시간 증가

`gpbackup`/`gprestore`가 바이너리 데이터까지 전부 덤프하므로, 파일을 많이 저장할수록 백업 크기·시간이 크게 늘어납니다.

### 6.3 분산키 선택

`file_id`로 분산하면 파일들이 세그먼트에 고르게 퍼지지만, 특정 파일에 매우 자주 접근하는 패턴이면 hotspot이 생길 수 있으니 워크로드에 맞게 조정하세요.

## 요약 비교표

| 방식 | 장점 | 단점 |
|---|---|---|
| **BYTEA 컬럼에 직접 저장** (본 문서 방식) | 트랜잭션 일관성 보장, 별도 스토리지 연동 불필요 | 대용량/다량 저장 시 백업·성능 부담 |
| **Object Storage + 경로만 DB 저장** | 대용량/대량 파일에 적합, 백업 가벼움 | 파일-DB 간 정합성 별도 관리 필요 |
| **Large Object (`lo_*`)** | (PostgreSQL 표준) | **WarehousePG에서 지원 안 함** |
