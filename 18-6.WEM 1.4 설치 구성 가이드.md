# 18-6 WEM 1.4 설치 구성 가이드

6노드 WarehousePG 7.5 환경에 WEM 1.4를 설치하는 절차입니다. Safeguard DR 구성은 [18-5 WEM 1.3 Safeguard DR 구성](./18-5.%20WEM%201.3%20Safeguard%20DR%20구성.md)을 참고합니다.

> 환경: Rocky Linux 9.5, WHPG 7.5, WEM 1.4.0, Host Agent 1.1.0 이상  
> 참고: [WEM 설치](https://www.enterprisedb.com/docs/supported-open-source/warehousepg/wem/installing/), [1.4 릴리스 노트](https://www.enterprisedb.com/docs/supported-open-source/warehousepg/wem/release_notes/1.4_rel_notes/)

## 1. 구성

| 호스트 | IP | 설치 구성요소 |
|---|---|---|
| cdw | 192.168.10.74 | Host Agent, OTel Collector |
| scdw | 192.168.10.75 | ClickHouse, PostgreSQL, WEM, Host Agent, OTel Collector |
| sdw1 | 192.168.10.76 | Host Agent, OTel Collector |
| sdw2 | 192.168.10.77 | Host Agent, OTel Collector |
| sdw3 | 192.168.10.78 | Host Agent, OTel Collector |
| sdw4 | 192.168.10.73 | Host Agent, OTel Collector |

WEM 상태 DB는 scdw의 PostgreSQL `127.0.0.1:5433/wem`, 메트릭·로그 저장소는 scdw의 ClickHouse `192.168.10.75:9000`입니다. WEM 웹 포트는 `8080`, Agent 연결 포트는 `8081`입니다.

## 2. 사전 준비 — cdw / gpadmin

```bash
source /usr/local/greenplum-db/greenplum_path.sh

cd /home/gpadmin/wem14
cat > all_hosts <<'EOF'
cdw

sdw1
sdw2
sdw3
sdw4
EOF

```

WEM 설치 전 scdw에서 cdw의 PostgreSQL `5432`에 `gpadmin`으로 접속할 수 있어야 합니다. 필요하면 WHPG의 `pg_hba.conf`에 scdw(`192.168.10.75/32`)의 `gpadmin`과 WEM 런타임 계정 `wem` 접속을 허용합니다. WEM은 설치 중 `wem` 역할을 생성합니다.

## 3. ClickHouse — scdw / root

```bash
export EDB_SUBSCRIPTION_TOKEN='<EDB_SUBSCRIPTION_TOKEN>'
export EDB_REPO=clickhouse
curl -1sSLf "https://downloads.enterprisedb.com/$EDB_SUBSCRIPTION_TOKEN/$EDB_REPO/setup.rpm.sh" | bash
dnf install -y edb-clickhouse-server edb-clickhouse-client
```

다른 노드가 접속할 수 있도록 수신 주소와 비밀번호를 설정합니다. `YOUR_CLICKHOUSE_PASSWORD`를 실제 비밀번호로 바꿉니다. XML의 `&`, `<`, `>`는 이스케이프해야 합니다.

```bash
mkdir -p /etc/clickhouse-server/config.d /etc/clickhouse-server/users.d
cat > /etc/clickhouse-server/config.d/observability.xml <<'EOF'
<clickhouse>
    <listen_host>0.0.0.0</listen_host>
</clickhouse>
EOF
cat > /etc/clickhouse-server/users.d/default-password.xml <<'EOF'
<clickhouse>
    <users>
        <default>
            <password>YOUR_CLICKHOUSE_PASSWORD</password>
        </default>
    </users>
</clickhouse>
EOF
systemctl enable --now clickhouse-server
clickhouse-client --host 192.168.10.75 --user default --password --query 'SELECT 1'
```
결과가 `1`이면 정상입니다. <br>

## 4. (옵션) WEM 상태용 PostgreSQL — scdw / root

WHPG와 별도의 PostgreSQL을 `/var/lib/pgsql/data`, 포트 `5433`에 설치합니다. 초기화는 **빈 데이터 디렉터리에서 한 번만** 실행합니다.

```bash
dnf install -y postgresql-server postgresql-contrib
install -d -m 700 -o postgres -g postgres /var/lib/pgsql/data
runuser -u postgres -- /usr/bin/initdb -D /var/lib/pgsql/data --auth-local=peer --auth-host=scram-sha-256
cat >> /var/lib/pgsql/data/postgresql.conf <<'EOF'
listen_addresses = '127.0.0.1'
port = 5433
password_encryption = 'scram-sha-256'
EOF
```

현재 환경과 동일하게 상태 DB 전용 서비스를 등록합니다.

```bash
cat > /etc/systemd/system/postgresql-wem14.service <<'EOF'
[Unit]
Description=PostgreSQL for WEM state
After=network.target

[Service]
Type=simple
User=postgres
Group=postgres
ExecStart=/usr/bin/postgres -D /var/lib/pgsql/data
KillSignal=SIGINT
Restart=on-failure

[Install]
WantedBy=multi-user.target
EOF
systemctl daemon-reload
systemctl enable --now postgresql-wem14
runuser -u postgres -- /usr/bin/psql -p 5433 -d postgres
```

`psql`에서 WEM 상태 DB 계정을 만듭니다.

```sql
CREATE ROLE wem_admin LOGIN CREATEDB;
\password wem_admin
\q
```

## 5. WEM — scdw / root

```bash
export EDB_SUBSCRIPTION_TOKEN='<EDB_SUBSCRIPTION_TOKEN>'
export EDB_REPO=gpsupp
curl -1sSLf "https://downloads.enterprisedb.com/$EDB_SUBSCRIPTION_TOKEN/$EDB_REPO/setup.rpm.sh" | bash
dnf install -y whpg-enterprise-manager
```

`/etc/wem/wem.conf`에 아래 값을 설정합니다. 비밀번호를 실제 값으로 바꾸고, ClickHouse URL에는 URL 인코딩된 비밀번호를 사용합니다. 예를 들어 `!`는 `%21`, `@`는 `%40`입니다. `WEM_COOKIE_SECRET`과 `WEM_AGENT_JOIN_SECRET`은 각각 `openssl rand -hex 32`로 생성합니다. <br>
외부에 메트릭 노출을 위해 OTEL_PROMETHEUS_SCRAPE_ENDPOINT=0.0.0.0:'<port>' 를 명시해야 합니다. <br>

```ini
WHPG_HOST=192.168.10.74
WHPG_PORT=5432
WHPG_DATABASE=postgres
WHPG_USER=gpadmin
WHPG_PASSWORD='<GPADMIN_DB_PASSWORD>'

WEM_HOST=127.0.0.1
WEM_PORT=5433
WEM_DATABASE=wem
WEM_USER=wem_admin
WEM_PASSWORD='<WEM_STATE_DB_PASSWORD>'

CLICKHOUSE_URL='clickhouse://default:<URL_ENCODED_CLICKHOUSE_PASSWORD>@192.168.10.75:9000'
PORT=8080
WEM_COOKIE_SECRET='<GENERATED_COOKIE_SECRET>'
WEM_INSECURE_COOKIES=1
WEM_ADMIN_PASSWORD='<WEB_ADMIN_PASSWORD>'
OTEL_PROMETHEUS_SCRAPE_ENDPOINT=0.0.0.0:'<PORT>'
WEM_AGENT_JOIN_SECRET='<GENERATED_JOIN_SECRET>'
```

`WEM_INSECURE_COOKIES=1`은 이 HTTP 테스트 환경에서만 사용합니다.

`WEM_AGENT_JOIN_SECRET`은 Host Agent의 수동 승인 절차를 생략하게 해 주는 공유 비밀 값입니다. <br>
에이전트 호스트의 `/etc/edb/acp-host-agent/join-token` 파일에 이 값과 같은 토큰이 있으면, 에이전트는 'Host Agents' 탭에서 대기하지 않고 즉시 '승인됨(approved)' 상태가 됩니다. 6절에서 모든 노드의 `join-token` 에 같은 값을 넣습니다. 자격 증명이므로 값이 노출되지 않게 관리합니다. <br>
이 값을 설정하지 않으면 관리자가 'Host Agents' 탭에서 모든 신규 에이전트를 명시적으로 승인해야 합니다.

```bash
systemctl enable --now wem
systemctl status wem --no-pager
```

웹 주소는 `http://192.168.10.75:8080/`입니다. 초기 계정은 `admin`, 비밀번호는 `WEM_ADMIN_PASSWORD` 값입니다.

## 6. Host Agent 설치 — cdw / gpadmin

cdw에 EDB `gpsupp` 저장소를 설정하고 패키지를 내려받아 6대에 배포합니다.

```bash
export EDB_SUBSCRIPTION_TOKEN='<EDB_SUBSCRIPTION_TOKEN>'
export EDB_REPO=gpsupp
curl -1sSLf "https://downloads.enterprisedb.com/$EDB_SUBSCRIPTION_TOKEN/$EDB_REPO/setup.rpm.sh" | sudo -E bash
cd /home/gpadmin/wem14
sudo dnf download edb-acp-host-agent edb-otelcol
gpsync -f all_hosts edb-acp-host-agent-*.rpm edb-otelcol-*.rpm =:/tmp
gpssh -f all_hosts -e 'sudo dnf install -y /tmp/edb-acp-host-agent-*.rpm /tmp/edb-otelcol-*.rpm'
```

6대의 `/etc/edb/acp-host-agent/acp-host-agent.conf`에서 WEM 주소와 대상 DB를 설정합니다.

```bash
gpssh -f all_hosts -e "sudo sed -i \
  -e 's|^WEM_CONNECT_ADDRESS=.*|WEM_CONNECT_ADDRESS=192.168.10.75:8081|' \
  -e 's|^WEM_DATABASE=.*|WEM_DATABASE=postgres|' \
  /etc/edb/acp-host-agent/acp-host-agent.conf"
```

Host Agent를 시작하기 **전에** 6대의 `/etc/edb/acp-host-agent/join-token` 에 5절의 `WEM_AGENT_JOIN_SECRET` 과 같은 값을 씁니다. 에이전트는 `acp-host-agent` 계정으로 실행되므로 파일 소유자를 이 계정으로, 권한을 `0600`으로 맞춥니다. 소유자가 root이면 에이전트가 파일을 읽지 못해 토큰 없이 등록되고 승인 대기 상태로 남습니다.

```bash
gpssh -f all_hosts -e "printf '%s' '<GENERATED_JOIN_SECRET>' | sudo tee /etc/edb/acp-host-agent/join-token >/dev/null && sudo chown acp-host-agent:acp-host-agent /etc/edb/acp-host-agent/join-token && sudo chmod 600 /etc/edb/acp-host-agent/join-token"
gpssh -f all_hosts -e 'sudo systemctl enable --now acp-host-agent'
```

에이전트 로그에 `self-registration succeeded` 와 `post-approval re-registration fetched segments` 가 보이고 `awaiting TLS material` 이 없으면 자동으로 승인된 것입니다. WEM UI의 **Management → Host Agents**에서도 Agent가 승인(approved) 상태로 보입니다.

```bash
gpssh -f all_hosts -e 'sudo grep -E "self-registration|post-approval|awaiting TLS" /var/log/edb/acp-host-agent/acp-host-agent.log | tail -3'
```

자동 승인이 되지 않고 `PENDING` 으로 남으면 Agent별 `/etc/edb/acp-host-agent/join-token`과 UI의 Verification Token을 비교한 뒤 수동으로 승인합니다. 승인 권한이 꺼져 있으면 **Management → Permissions**에서 Admin의 **Approve Host Agent**를 활성화합니다.

승인 후 WEM이 Collector 설정을 배포하고 서비스를 시작할 수 있습니다.

## 주의 3. OTel Collector 설정 수정 방법 (acp-host-agent 재시작 시에도 유지)
### 문제
Otelcol's CPU usage dropped from around 30% to the single-digit range. <br>
`/etc/edb/otelcol/config.yml`을 수정하고 `edb-otelcol` 서비스를 restart 하면 정상 동작하지만, `acp-host-agent` 서비스를 restart 하면 수정한 값이 원복됩니다.

### 해결 방법

원본 `config.yaml`은 그대로 두고, 별도의 override 파일(`config_local.yaml`)을 만들어 `edb-otelcol`이 함께 읽도록 설정합니다. 이렇게 하면 `acp-host-agent`를 restart 해도 수정한 값이 유지됩니다.

#### 3-1. Override 파일 생성

`/etc/edb/otelcol/config_local.yaml`을 만들고 override 할 값을 추가합니다.

```bash
sudo tee /etc/edb/otelcol/config_local.yaml << EOF
# config_local.yaml — Add values to override.
receivers:

  file_log:
    start_at: end      # beginning -> end, begining으로 하면 기존 모든 로그 화일을 수집할 동안 CPU을 과도하게 많이 사용합니다. 
    poll_interval: 1s  # add new

processors:

  batch:
    send_batch_size: 8192        # 1024 -> 8192
    send_batch_max_size: 16384   # 2048 -> 16384
    timeout: 5s                  # 10s -> 5s
EOF
```

#### 3-2. 파일 소유자를 `edb-otelcol`로 변경

```bash
sudo chown edb-otelcol:edb-otelcol /etc/edb/otelcol/config_local.yaml
```

#### 3-3. 설정 확인 (병합 결과 출력)

```bash
sudo /usr/edb/otelcol/bin/edb-otelcol print-config \
  --config=file:/etc/edb/otelcol/config.yaml \
  --config=file:/etc/edb/otelcol/config_local.yaml
```

#### 3-4. 설정 유효성 검사

```bash
sudo /usr/edb/otelcol/bin/edb-otelcol validate \
  --config=file:/etc/edb/otelcol/config.yaml \
  --config=file:/etc/edb/otelcol/config_local.yaml
```

#### 3-5. `edb-otelcol.conf` 수정

```bash
sudo tee /etc/edb/otelcol/edb-otelcol.conf << EOF
OTELCOL_OPTIONS="--config /etc/edb/otelcol/config.yaml --config /etc/edb/otelcol/config_local.yaml"
EOF
```

#### 3-6. 서비스 재시작
acp-host-agent 를 재시작 해도 됨. 
```bash
sudo systemctl restart edb-otelcol
```

#### 3-7. 상태 확인
```bash
sudo systemctl status edb-otelcol --no-pager
```

## 주의 4. Coordinator Query Logs 분리 수집 설계 (ClickHouse)

### 4-1. (옵션) 기존에 있으면 삭제(DROP) 

```sql
DROP VIEW IF EXISTS acp_observability.coordinator_query_logs;
DROP VIEW IF EXISTS acp_observability.mv_coordinator_query_logs_states;
DROP TABLE IF EXISTS acp_observability.coordinator_query_logs_states;
```

### 4-2. 신규 생성(CREATE)한 객체 `coordinator_query_logs_states` (AggregatingMergeTree)

```sql
CREATE TABLE acp_observability.coordinator_query_logs_states
(
    `EventDate`         Date,
    `TxId`              String,
    `CommandTag`        String,

    `Database`          SimpleAggregateFunction(any, String),
    `LogUser`           SimpleAggregateFunction(any, String),
    `SessionId`         SimpleAggregateFunction(any, String),
    `ConnectionFrom`    SimpleAggregateFunction(any, String),
    `SessionStart`      SimpleAggregateFunction(any, String),
    `ClusterIdentity`   SimpleAggregateFunction(any, String),
    `FileName`          SimpleAggregateFunction(any, String),
    `LogFilePath`       SimpleAggregateFunction(any, String),
    `LogPid`            SimpleAggregateFunction(any, String),
    `WhpgHost`          SimpleAggregateFunction(any, String),

    `FirstTimestamp`    AggregateFunction(min, DateTime64(9)),
    `LastTimestamp`     AggregateFunction(max, DateTime64(9)),
    `QueryText`         AggregateFunction(argMin, String, Tuple(UInt8, DateTime64(9))),
    `DurationMs`        AggregateFunction(max, Float64),
    `LineCount`         AggregateFunction(count),
    `RelatedMessages`   AggregateFunction(groupArray, String),
    `Severities`        AggregateFunction(groupUniqArray, String),

    `HasError`          AggregateFunction(max, UInt8),
    `ErrorSqlState`     AggregateFunction(argMax, String, UInt8),
    `ErrorMessage`      AggregateFunction(argMax, String, UInt8),
    `ErrorDetail`       AggregateFunction(argMax, String, UInt8),
    `ErrorHint`         AggregateFunction(argMax, String, UInt8)
)
ENGINE = AggregatingMergeTree
PARTITION BY toYYYYMM(EventDate)
ORDER BY (EventDate, TxId, CommandTag)
TTL EventDate + INTERVAL 90 DAY
SETTINGS index_granularity = 8192;
```

### 4-3. `mv_coordinator_query_logs_states` (Materialized View)

```sql
CREATE MATERIALIZED VIEW acp_observability.mv_coordinator_query_logs_states
TO acp_observability.coordinator_query_logs_states
AS
WITH
    LogAttributes['message'] AS msg,
    LogAttributes['severity'] AS sev,
    LogAttributes['sql_state'] AS sqlstate,
    LogAttributes['detail'] AS detail_f,
    LogAttributes['hint'] AS hint_f,
    match(
        msg,
        '(?s)^(?:duration:\s*[0-9.]+\s*ms\s*)?(?:statement|execute\s+\S+):'
    ) AS is_query_line,
    (sev = 'ERROR') AS is_error_line,
    extractGroups(msg, '(?s)^duration:\s*([0-9.]+)\s*ms') AS dur_g
SELECT
    toDate(Timestamp)                      AS EventDate,
    LogAttributes['txid']                  AS TxId,
    LogAttributes['command_tag']           AS CommandTag,

    any(LogAttributes['database'])         AS Database,
    any(LogAttributes['log_user'])         AS LogUser,
    any(LogAttributes['session_id'])       AS SessionId,
    any(LogAttributes['connection_from'])  AS ConnectionFrom,
    any(LogAttributes['session_start'])    AS SessionStart,
    any(LogAttributes['cluster_identity']) AS ClusterIdentity,
    any(LogAttributes['file_name'])        AS FileName,
    any(LogAttributes['log.file.path'])    AS LogFilePath,
    any(LogAttributes['log_pid'])          AS LogPid,
    any(LogAttributes['whpg_host'])        AS WhpgHost,

    minState(Timestamp)                                              AS FirstTimestamp,
    maxState(Timestamp)                                              AS LastTimestamp,
    argMinState(msg, tuple(if(is_query_line, 0, 1), Timestamp))      AS QueryText,
    maxState(toFloat64OrZero(dur_g[1]))                              AS DurationMs,
    countState()                                                     AS LineCount,
    groupArrayIfState(msg, NOT is_query_line)                        AS RelatedMessages,
    groupUniqArrayState(sev)                                         AS Severities,

    maxState(toUInt8(is_error_line))                                 AS HasError,
    argMaxState(sqlstate, toUInt8(is_error_line))                    AS ErrorSqlState,
    argMaxState(msg, toUInt8(is_error_line))                         AS ErrorMessage,
    argMaxState(detail_f, toUInt8(is_error_line))                    AS ErrorDetail,
    argMaxState(hint_f, toUInt8(is_error_line))                      AS ErrorHint
FROM acp_observability.otel_logs
WHERE LogAttributes['log_segment'] = 'seg-1'
  AND LogAttributes['log_user'] != 'wemon'
  AND LogAttributes['txid'] != ''
  AND LogAttributes['command_tag'] != ''
GROUP BY EventDate, TxId, CommandTag;
```

### 4-4. `coordinator_query_logs` (최종 조회용 View)

```sql
CREATE VIEW acp_observability.coordinator_query_logs AS
SELECT
    TxId,
    CommandTag,
    any(Database)                         AS Database,
    any(LogUser)                          AS LogUser,
    any(SessionId)                        AS SessionId,
    any(ConnectionFrom)                   AS ConnectionFrom,
    any(SessionStart)                     AS SessionStart,
    any(ClusterIdentity)                  AS ClusterIdentity,
    any(FileName)                         AS FileName,
    any(LogFilePath)                      AS LogFilePath,
    any(LogPid)                           AS LogPid,
    any(WhpgHost)                         AS WhpgHost,

    minMerge(FirstTimestamp)              AS FirstTimestamp,
    maxMerge(LastTimestamp)                AS LastTimestamp,
    argMinMerge(QueryText)                 AS QueryText,
    nullIf(maxMerge(DurationMs), 0)         AS DurationMs,
    countMerge(LineCount)                   AS LineCount,
    groupArrayMerge(RelatedMessages)        AS RelatedMessages,
    groupUniqArrayMerge(Severities)         AS Severities,

    maxMerge(HasError)                      AS HasError,
    argMaxMerge(ErrorSqlState)               AS ErrorSqlState,
    argMaxMerge(ErrorMessage)                AS ErrorMessage,
    argMaxMerge(ErrorDetail)                 AS ErrorDetail,
    argMaxMerge(ErrorHint)                   AS ErrorHint
FROM acp_observability.coordinator_query_logs_states
GROUP BY TxId, CommandTag;
```

### 4-6. 현재 상태 / 남은 작업

- ✅ Coordinator query 로그가 실시간으로 `(TxId, CommandTag)` 단위 1행으로 통합 수집되는 중
- ✅ `wemon` 사용자 로그 제외 적용됨
- ✅ Coordinator failover 상황에도 수집이 끊기지 않도록 설계(`log_segment='seg-1'` + `txid/command_tag not empty` 기반, `whpg_host` 하드코딩 없음)
- ⏳ `DurationMs`는 현재 전부 `NULL` — GPDB(coordinator) `postgresql.conf`의 `log_min_duration_statement` 설정이 아직 비활성 상태이기 때문 (별도 조치 필요)
- ⏳ 과거 데이터 백필 미수행 — 필요 시 아래 쿼리 실행 가능

```sql
INSERT INTO acp_observability.coordinator_query_logs_states
WITH
    LogAttributes['message'] AS msg,
    LogAttributes['severity'] AS sev,
    LogAttributes['sql_state'] AS sqlstate,
    LogAttributes['detail'] AS detail_f,
    LogAttributes['hint'] AS hint_f,
    match(
        msg,
        '(?s)^(?:duration:\s*[0-9.]+\s*ms\s*)?(?:statement|execute\s+\S+):'
    ) AS is_query_line,
    (sev = 'ERROR') AS is_error_line,
    extractGroups(msg, '(?s)^duration:\s*([0-9.]+)\s*ms') AS dur_g
SELECT
    toDate(Timestamp)                      AS EventDate,
    LogAttributes['txid']                  AS TxId,
    LogAttributes['command_tag']           AS CommandTag,
    any(LogAttributes['database'])         AS Database,
    any(LogAttributes['log_user'])         AS LogUser,
    any(LogAttributes['session_id'])       AS SessionId,
    any(LogAttributes['connection_from'])  AS ConnectionFrom,
    any(LogAttributes['session_start'])    AS SessionStart,
    any(LogAttributes['cluster_identity']) AS ClusterIdentity,
    any(LogAttributes['file_name'])        AS FileName,
    any(LogAttributes['log.file.path'])    AS LogFilePath,
    any(LogAttributes['log_pid'])          AS LogPid,
    any(LogAttributes['whpg_host'])        AS WhpgHost,
    minState(Timestamp)                                              AS FirstTimestamp,
    maxState(Timestamp)                                              AS LastTimestamp,
    argMinState(msg, tuple(if(is_query_line, 0, 1), Timestamp))      AS QueryText,
    maxState(toFloat64OrZero(dur_g[1]))                              AS DurationMs,
    countState()                                                     AS LineCount,
    groupArrayIfState(msg, NOT is_query_line)                        AS RelatedMessages,
    groupUniqArrayState(sev)                                         AS Severities,
    maxState(toUInt8(is_error_line))                                 AS HasError,
    argMaxState(sqlstate, toUInt8(is_error_line))                    AS ErrorSqlState,
    argMaxState(msg, toUInt8(is_error_line))                         AS ErrorMessage,
    argMaxState(detail_f, toUInt8(is_error_line))                    AS ErrorDetail,
    argMaxState(hint_f, toUInt8(is_error_line))                      AS ErrorHint
FROM acp_observability.otel_logs
WHERE LogAttributes['log_segment'] = 'seg-1'
  AND LogAttributes['log_user'] != 'wemon'
  AND LogAttributes['txid'] != ''
  AND LogAttributes['command_tag'] != ''
GROUP BY EventDate, TxId, CommandTag;
```
